# CLI Mode — Embedded Claude Code Terminal + Live HTML Artifact

**Status:** Design (approved for spec review)
**Date:** 2026-09-04
**Type:** Additive experimental feature
**Related:** [`2026-09-01-workphlo-design.md`](./2026-09-01-workphlo-design.md)

## Problem

Workphlo's current session experience is the curated **live document**: typed
sections, each generated by a "hat", assembled into `document.md`. When a user
creates a new session and starts typing in the `PromptBar`, they lose the
**full power and visibility of the Claude Code CLI** — the interactive TUI,
the ability to see the agent working turn-by-turn, tool calls, and the raw
CLI feature surface.

This feature adds an experimental **CLI Mode**: an embedded, real `claude`
terminal so the user drives and *watches* a full CLI session, while a
side-by-side pane renders a polished HTML artifact the agent is steered to
produce. It is additive — the existing document flow is untouched.

## Goals

- Run the **real `claude` CLI interactively** inside a Workphlo pane (full
  fidelity, full visibility), not a headless NDJSON subprocess.
- Steer the CLI, via an **implicit on-disk skill + system-prompt append**, to
  write its final result as a **complete, styled HTML document** to a known
  path.
- Render that HTML **live** beside the terminal, reusing the existing
  sandboxed-iframe renderer.
- Keep it a **new, additive mode** behind a session type. Zero change to the
  live-document behavior.

## Non-Goals (YAGNI for the experiment)

- PTY session resume across app restarts.
- Multiple terminals per session.
- Editing `result.html` back into the agent / round-tripping.
- Reconciling terminal output into the structured `document.md` sections.
- Rich terminal theming beyond a sane default.

## Decisions (from brainstorming)

| Question | Decision |
|---|---|
| Visibility model | **Embed the real CLI** (node-pty + xterm.js) |
| Scope | **New experimental mode, additive** |
| Result surface | **Split view: terminal + live HTML artifact pane** (reuse `HtmlBody`) |
| Steering mechanism | **Injected skill + system-prompt append** |

## Architecture

The one architecture that respects Electron's security boundary
(`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, renderer
never spawns):

```
┌─ renderer ──────────────────────────────┐        ┌─ main (Node) ───────────────────────┐
│ CliSessionView                           │        │ ptyHost (node-pty)                  │
│  ├─ TerminalPane (xterm.js)              │        │   spawns interactive `claude`       │
│  │     keystrokes ──wf:pty:input───────────────▶  │   in session cwd                    │
│  │     bytes      ◀──wf:pty:data────────────────  │   emits data / exit                 │
│  │     resize     ──wf:pty:resize──────────────▶  │                                     │
│  └─ ArtifactPane (HtmlBody sandbox iframe)│        │ artifactWatcher                     │
│        html       ◀──wf:artifactUpdate──────────  │   fs.watch(<cwd>/result.html)       │
└──────────────────────────────────────────┘        │ createSession scaffolds skill+cwd   │
                                                     └─────────────────────────────────────┘
```

`node-pty` runs only in main; `xterm.js` only in the renderer; bytes cross the
existing preload bridge. No new trust boundary is introduced — the HTML
artifact renders in the **same locked-down `sandbox="allow-scripts"` iframe
with per-render nonce CSP** already used by `HtmlBody` in
`src/renderer/src/sections/renderers.tsx`.

## Components

### 1. Session mode (additive)

- `SessionMeta` (in `src/shared/types.ts`) gains `mode: 'document' | 'cli'`,
  defaulting to `'document'` for backward compatibility (older `session.json`
  without the field reads as `'document'`).
- `createSession` (`src/main/workspace/workspace.ts`) accepts `mode`. For
  `mode: 'cli'` it **skips** document scaffolding (no `document.md` sections)
  and instead scaffolds the CLI working dir (see §3).
- IPC `wf:createSession` (`src/main/ipc.ts`) — today hard-codes
  `template: 'spec-design'`, `engine: 'cli'` — takes a `mode` param and routes
  accordingly. (Note: the existing `engine: 'cli'` value is the *headless
  EngineKind*, unrelated to this feature's `mode: 'cli'`; the two names are
  distinct concepts. See Risks.)
- Tree/new-session UI (`TreePane.tsx`) offers "Terminal / CLI" as a session
  type alongside the current document session.

### 2. PTY host (main) — `src/main/pty/ptyHost.ts`

- Uses `node-pty`. `startPty({ sessionId, cwd, model, cols, rows })`:
  - Spawns the `claude` binary **interactively** (no `-p`), `cwd` = the
    session working dir (§3), with:
    - `--append-system-prompt <steering text>` (§3),
    - `--model <resolved model>` using the existing model-resolution default,
    - environment inherited from the app.
  - Tracks one live pty per `sessionId` (map). Rejects a second start for a
    session already running.
  - Exposes `write(sessionId, data)`, `resize(sessionId, cols, rows)`,
    `kill(sessionId)`.
  - Emits `data` (chunk) and `exit` ({ code, signal }).
- **Testability:** the spawn function is injected (constructor/factory param),
  mirroring how `SdkEngine`'s `query` is injectable — unit tests pass a fake
  pty that echoes writes and can emit exit.
- **Interrupt:** `kill` sends `SIGINT` first (equivalent to the user's Ctrl-C),
  escalating to `SIGTERM` if the process does not exit within a short grace
  window.

### 3. Implicit HTML skill + steering — `src/main/pty/scaffold.ts`

On CLI-session create, scaffold the session working dir:

- `<cwd>/.claude/skills/workphlo-html-report/SKILL.md` — a skill instructing
  Claude to write its **final** result as a **complete, self-contained, styled
  HTML document** to `<cwd>/result.html`, with a defined top-level structure
  (title, summary, body sections) and semantic class names the ArtifactPane can
  style. The skill is discovered automatically by the CLI from the project
  `.claude/skills/` directory.
- `--append-system-prompt` reinforces, per run: "When you have a result to
  present, use the workphlo-html-report skill and write/update
  `result.html` in the working directory."

Both artifacts are plain files on disk — inspectable and editable by the user,
which is the point of "implicit skills/prompt."

### 4. Artifact watcher (main) — `src/main/pty/artifactWatcher.ts`

- `watchArtifact(sessionId, cwd)` watches `<cwd>/result.html`
  (`fs.watch` with a debounce, ~150 ms, to coalesce rapid writes).
- On change: read the file, push `{ sessionId, html }` over `wf:artifactUpdate`.
- Handles the file not yet existing (starts empty; first write triggers the
  push). Stops on session close / pty exit.

### 5. IPC + preload

New channels (added to `src/main/ipc.ts` and the `window.workphlo` bridge in
`src/preload/index.ts` + `api.d.ts`):

| Channel | Direction | Payload |
|---|---|---|
| `wf:pty:start` | renderer→main (invoke) | `{ sessionId, cols, rows }` |
| `wf:pty:input` | renderer→main | `{ sessionId, data }` |
| `wf:pty:resize` | renderer→main | `{ sessionId, cols, rows }` |
| `wf:pty:kill` | renderer→main | `{ sessionId }` |
| `wf:pty:data` | main→renderer (push) | `{ sessionId, data }` |
| `wf:pty:exit` | main→renderer (push) | `{ sessionId, code, signal }` |
| `wf:artifactUpdate` | main→renderer (push) | `{ sessionId, html }` |

`wf:pty:start` is guarded by the existing per-session in-flight pattern where
applicable. Pushes are scoped by `sessionId`; the renderer ignores events for
non-active sessions.

### 6. Renderer

- **Deps:** add `xterm` and `@xterm/addon-fit` (renderer-only).
- `TerminalPane.tsx` — mounts an xterm instance into a container, calls
  `wf:pty:start` on mount, pipes `onData` → `wf:pty:input`, subscribes to
  `wf:pty:data` → `term.write`, wires the fit addon + `ResizeObserver` →
  `wf:pty:resize`, and shows an inline banner on `wf:pty:exit` or spawn error.
- `ArtifactPane.tsx` — subscribes to `wf:artifactUpdate` for the active
  session and renders the HTML through the **existing `HtmlBody`** component
  (imported/factored from `renderers.tsx`). Empty state before first write.
- `CliSessionView.tsx` — split layout (terminal on one side, artifact on the
  other; simple draggable or fixed split for v1).
- `App.tsx` — selects `CliSessionView` when the active session's
  `mode === 'cli'`, else the existing `SectionCanvas` shell.
- Store (`store.ts`) — add minimal CLI-session state (active pty status,
  latest artifact html) and IPC subscriptions, kept separate from the
  document/section state.

### 7. Native module build

`node-pty` is a native addon and must be rebuilt against the Electron ABI.

- Add `@electron/rebuild` and a `postinstall` (or an explicit documented
  `npm run rebuild`) step.
- Ensure `node-pty` is treated as an external/commonjs dependency in
  `electron.vite.config.ts` for the main process (not bundled).
- Document the rebuild in `README.md`.

## Data Flow

1. User creates a **CLI session** → `wf:createSession { mode: 'cli' }`.
2. Main `createSession` writes `session.json` (`mode: 'cli'`) and scaffolds the
   working dir with `.claude/skills/workphlo-html-report/` (§3). No
   `document.md` sections.
3. Renderer opens `CliSessionView`; `TerminalPane` calls `wf:pty:start`.
4. Main `ptyHost` spawns interactive `claude` in the cwd with the appended
   system prompt + model; `artifactWatcher` begins watching `result.html`.
5. User types in xterm; keystrokes → `wf:pty:input` → pty. Claude's output
   streams back via `wf:pty:data` → xterm — the user watches it work.
6. Claude writes/updates `result.html` → watcher debounces, reads, pushes
   `wf:artifactUpdate` → `ArtifactPane` re-renders the styled HTML live.
7. Closing the session / killing the pty stops the watcher and the process.

## Error Handling

- **`claude` not on PATH / spawn failure:** `ptyHost` emits an error → renderer
  shows a banner in the terminal pane with the failure and remediation.
- **pty exit (crash or normal):** `wf:pty:exit` → banner with code/signal; user
  can restart the session.
- **Malformed `result.html`:** renders best-effort inside the existing sandbox
  (already isolated; cannot escape). No crash of the app.
- **Watcher race (file mid-write):** debounce + read-with-retry on transient
  read errors.
- **Renderer sends input for a dead pty:** main no-ops and logs.

## Testing

- **Unit (Vitest):**
  - `ptyHost` with an injected fake pty: start tracks the session, `write`
    forwards bytes, `resize` forwards dims, `kill` sends SIGINT then SIGTERM,
    duplicate start is rejected, `exit` is emitted.
  - `scaffold` writes the skill file + expected structure into the cwd.
  - `artifactWatcher` debounces bursts into a single push, handles
    not-yet-existing file, stops cleanly.
- **E2E (Playwright):** light smoke — creating a CLI session mounts
  `CliSessionView` and the terminal element; ArtifactPane shows its empty
  state. (Driving a real interactive pty in Playwright is out of scope; the
  pty is exercised by unit tests with a fake.)

## Risks & Open Points

- **Native module friction.** `node-pty` + Electron rebuild is the main setup
  cost and the likeliest breakage on `npm install`. Mitigated by
  `@electron/rebuild` + docs; must be verified on the target platform (darwin).
- **Naming collision.** The existing `EngineKind = 'cli' | 'sdk'` (headless
  execution adapter) is a *different* concept from this feature's session
  `mode: 'cli'` (interactive embedded terminal). Keep names distinct in code
  (`mode` vs `engine`) and comment the distinction to avoid confusion.
- **Working directory.** v1 uses the session dir as `cwd`. Repo/project access
  (`repo.paths`) is still a placeholder in the current codebase; pointing CLI
  Mode at a real project dir is a follow-up.
- **Model resolution.** CLI Mode reuses the workspace default model via
  `--model`; per-session model choice UI is a follow-up if wanted.
